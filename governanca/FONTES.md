# Fontes e Rastreabilidade

## 1. Fontes de trabalho utilizadas

1. **Regras escritas nesta conversa:** modelagens, capuz, punho, costura, bainhas, posicionamento, linhas, tecidos, viés, escudos, SISBolt, arquivos de Atalhos, devolução e revisão integral.
2. **MAN-DES-001 Manual Geral v0.2** (PDF/DOCX): base documental do fluxo integrado e organização por etapa.
3. **CHK-DES-GERAL-001 Checklists Integrados v0.2** (PDF/DOCX): referência histórica da estrutura de verificações.
4. **Manuais de Saída de Artes POP-DES-001 v1.4 a v1.8**: evolução das regras e responsabilidades técnicas.
5. **Checklists CHK-DES-001 v1.0 a v1.4**: base para critérios de inspeção e evidências.
6. **Gabaritos - Moldes.pdf**: dez pranchas de referência de modelagem e legendas de tecido.
7. **Atalhos Saídas - Neuber.pdf/.cdr e exemplos PNG**: exemplos reais, **não** padrões universais de medida.
8. **Notes.pdf** e ZIPs de reuniões/anotações: fontes históricas parciais; requerem revisão visual completa.
9. **Saídas de Emergência** e **Ajustar pedidos**: registros de ocorrências e dúvidas; contextos e versões precisam ser verificados antes de generalizar.
10. **Layautistas.zip**: material adicional de criação, ainda sem inventário exaustivo.
11. **Matriz de rastreabilidade / relatório de auditoria v0.1**: inventário preliminar, não homologação.
12. **Mapas de fluxo** produzidos anteriormente: geral e por etapa; disponíveis para incorporação futura em assets.

## 2. Limites desta transcrição inicial em Markdown

- Nem todos os ZIPs de histórico, suas mídias e anotações manuscritas foram auditados item a item.
- O repositório inicia com **texto operacional consolidado**, não com uma cópia integral dos PDFs/DOCX e não com os arquivos pessoais de grupos.
- Quando uma ocorrência foi interpretada como padrão de trabalho, o alcance deve ser revisado contra o pedido original.
- Dados de clientes, telefones, CPFs, nomes e conversas privadas não devem ser expostos num repositório público.
- A presença de uma regra neste manual **não comprova aprovação formal** pelo setor.

## 3. Registro recomendado para novos requisitos

| Campo | Exemplo |
|---|---|
| Código | REQ-SAI-0001 |
| Origem | Mensagem de liderança / gabarito / ocorrência |
| Data | AAAA-MM-DD |
| Texto original | Transcrição sem interpretação |
| Interpretação | Regra operacional proposta |
| Abrangência | Linha, peça, operação |
| Situação | Confirmada / exceção / histórica / pendente |
| Local no manual | Arquivo e título |
| Checklist afetado | Código |
| Evidência | Documento/arquivo autorizado |
| Homologação | Quem validou e quando |

## 4. Arquivos originais

Não publicar conteúdo interno ou de clientes sem autorização. Documentação Markdown pode apontar para anexo controlado, repositório privado ou armazenamento corporativo com permissões adequadas. A simples existência de um arquivo na conversa não significa que deva ser enviado ao GitHub público.
